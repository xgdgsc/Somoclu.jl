Compared to C++ Somoclu

Somoclu.jl reimplements the C++ Somoclu algorithms in pure Julia. There is no C++ / binary dependency.

Version numbering tracks the upstream library line (currently aligned with the Python package’s 1.7.x series).

Sparse path details

  • Input: SparseMatrixCSC of size nDimensions × nVectors (columns = samples).
  • Algorithm: Same as C++ non-MPI trainOneEpochSparseCPU: BMU via $‖x‖² + ‖w‖² − 2⟨w,x⟩$, then neighbourhood-weighted update using only nonzero features. Missing features contribute 0 to the numerator (so those codebook dimensions become 0 when the denominator is nonzero).
  • Codebook remains dense.
  • som.backend is ignored for sparse train! (CPU + Threads.@threads).
  • Dense KA/PoCL and sparse CPU can diverge across epochs even on “fully dense” data because dense BMUs use √ΣΔ² while sparse BMUs use the squared formula; float tie-breaks differ. Prefer one path consistently.
using SparseArrays, Somoclu
X = sprand(Float32, 20_000, 1_000, 0.005)
som = Som(50, 40; gridtype="rectangular", compactsupport=true)
train!(som, X; epochs=15)

Intentionally preserved quirks

  • Internal map size: nSomX = nrows, nSomY = ncolumns (historical Julia wrapper).
  • gridtype="square" uses hexagonal map distances (C++ only special-cases "rectangular").
  • Default compactsupport=true matches the historical Julia/Python wrapper (CLI default is false).

Not planned as C++ clones

MPI, CLI, and ESOM-style file IO are omitted for now. MPI is feasible later with MPI.jl (broadcast codebook / reduce numerator–denominator per epoch) if multi-node scaling is needed.
